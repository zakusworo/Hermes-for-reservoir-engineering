# Exercise 2: Give Specific Context

**Best practice:** name the file, function, failing test, and observed symptom.

## Scenario

`pvt_conversions.py` has a subtle unit conversion bug. The function is supposed to convert API gravity to oil specific gravity and back.

## Engineering Context

This exercise is intentionally small because real engineering defects often hide inside "obvious" helper functions. API gravity is not just a label; it determines which correlations and property ranges are reasonable.

Use the standard relationship:

```text
SG = 141.5 / (API + 131.5)
API = 141.5 / SG - 131.5
```

The visual check below gives Claude and the engineer a quick sanity test: as API increases, oil specific gravity decreases.

![API to specific gravity relationship](../assets/pvt_api_specific_gravity.png)

Reference points generated by `../scripts/generate_course_figures.py`:

- 22 API -> SG about 0.922
- 35 API -> SG about 0.850
- 42 API -> SG about 0.816

## What Makes A Good Prompt Here

The prompt should give Claude:

- the exact file and function names
- the failing test name
- the formula, including parentheses
- the expected monotonic behavior
- the command to run after editing

## Before Prompt

```text
Fix the PVT bug.
```

## After Prompt

```text
The test test_round_trip_api_specific_gravity in 02_specific_context/test_pvt_conversions.py fails.
Read 02_specific_context/pvt_conversions.py and fix api_to_specific_gravity or specific_gravity_to_api.
The petroleum engineering relationship is SG = 141.5 / (API + 131.5).
Run python3 -m pytest 02_specific_context/ -v after the edit.
```

## Extra Verification Ideas

After the basic round-trip test passes, ask Claude to add one more test:

```text
Add a monotonicity test proving that specific gravity decreases as API gravity increases from 22 to 42 API.
```

That check is useful because a round-trip conversion can pass even when both directions share a mirrored mistake.
